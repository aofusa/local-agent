# ローカル文書の map-reduce 設計

- 文書種別: 改修設計（実装前）
- 版: 0.1（2026-10-04）
- 対象: [aofusa/local-agent](https://github.com/aofusa/local-agent)
- 関係: チャットタブに、検索と並列の入口を足す。読解カードの形は `claim-verification-design.md` の `EvidenceCard` に合わせ、検証段を共有する
- 拘束: `AGENTS.md`。画像グラフは触らない。外向き通信は開かない

## 1. 結論

利用者が許可したディレクトリのテキストを、検索の reader と同じ幅 3 で読み、節ごとの抜粋カードに落とす。カバー漏れは 1 回だけ指摘し、統合はカードに書いてあることだけを日本語で返す。任意パスは読まない。ネットワークは使わない。

検索の「計画 → 並列取得 → フィルタ → 読解 → 批評 → 統合」の取得先を、Tor からローカルファイルに差し替える。新しい協調フレームワークは入れない。

## 2. この文書の使い方

実装前の契約である。許可ルート、拒否名、チャンク上限、ロックの順が本書と食い違ったら本書を優先する。主張の支持判定の中身は `claim-verification-design.md` に任せ、本書はカードを渡すところまでを主契約にする。

## 3. 現状

チャットタブは会話と Tor 検索だけを持つ。ローカルの README、設計書、CHANGELOG、ログを読ませる経路は無い。検索の reader は URL の本文を事実・数値・日付・反証に潰して返す。この潰し方を、ファイルの節に再利用する。

制約は検索と同じである。

- 検索モデルは PrismML の llama.cpp fork だけ。LM Studio と ComfyUI には入れない
- 常駐させない。使い終わったら PID を殺す
- llama-server にプロキシを渡さない。起動ごとにランダムな api-key
- LM Studio の 27B と reader は同時に載らない。計画のあと unload する
- 画像タブとチャットタブは `job_lock` で直列。ロックを放すのはワーカーが消え、unload のあと
- 幅は 3 まで。`langgraph-swarm` 等は使わない

## 4. 要件

### 4.1 やる

- チャットの `/docs` で、許可ルート配下のファイルまたはディレクトリを 1 件読む
- 質問が無ければ「この範囲の要点」を聞くものとして扱う
- オーケストレータが列挙、拒否、チャンク分割を行う。モデルはパスを決めない
- チャンクを最大 3 本並列で map し、`EvidenceCard`（`source_type=file`）を返す
- 未読の節があれば批評が 1 回だけ、次の波で読む節を最大 3 つ指名する。波は 4 まで（チャンク 12）
- 統合はカードだけを見る。主張検証を有効にしていれば、検索と同じ `claim_extract` 以降に入る
- 許可ルートが空なら機能はオフ。`/docs` は「LOCAL_DOC_ROOTS が未設定」と返す

### 4.2 やらない

- 許可ルートの外、シンボリックリンクの脱出、デバイスファイル
- `.env`、鍵、資格情報、`.git`、`node_modules`、生成画像、チェックポイントの読取
- ファイルの実行、書き込み、削除、移動
- モデルにツールとしてシェルを渡すこと
- Tor、クラウド、埋め込みインデックスの常設、ベクトル DB
- ディレクトリの再帰を無制限にすること
- 画像タブとの同時実行、文書からの画像生成への自動引き渡し
- バイナリの OCR、PDF の描画。PDF は対象外（テキストと Markdown のみ）
- ワーカー同士の議論

## 5. 設計

### 5.1 入口

チャットタブの `route` に文書分岐を足す。検索判定より先に `/docs` を見る。

```text
/docs <path> [質問]
```

- `path` は 1 つ。空白を含むときは引用符で囲む
- 質問を省略したときは「要点、決定、未決を、出典の節付きで」とする
- 画像添付は現行どおり画像タブへ誘導する。`/docs` と画像は同時に受けない

グラフ:

```text
ingest → route
  ├─ /docs → doc_resolve → doc_plan → doc_map (波、幅 3)
  │            → doc_cover → synthesize → claim_extract → claim_verify
  │            → claim_audit → claim_drop
  ├─ 検索 → 現行
  └─ 会話 → 現行
```

`CLAIM_VERIFY=0` のときは `synthesize` のあと終わる。検証の中身は別紙。

### 5.2 許可と拒否

`.env` の `LOCAL_DOC_ROOTS` はカンマ区切りの絶対パス。既定は空。空はオフ。

解決規則（オーケストレータ、LLM なし）:

1. 与えられたパスを絶対パスにする
2. 実パス（`realpath`）が、いずれかのルートの実パス配下であることを確認する。接頭辞の文字列比較だけでは不可
3. シンボリックリンクは実パスで再判定する。ルートの外に出たら拒否
4. ディレクトリなら、深さ 4 まで、ファイル数 30 まで列挙する。31 件目は捨て、進捗に件数を出す
5. ファイルならその 1 件。ディレクトリでもファイルでも、拡張子は `.md` `.txt` `.log` `.json` `.toml` `.yaml` `.yml` のみ

拒否名（大小無視、パス成分のどこにあっても拒否）:

```text
.env
.env.*
id_rsa
*.pem
*.key
*.pfx
credentials*
secret*
node_modules
.git
__pycache__
outputs
output
*.safetensors
*.gguf
*.png
*.jpg
```

`LOCAL_DOC_ROOTS` にリポジトリルートを入れてよい。拒否名が `.env` と鍵を落とす。許可ルートそのものをホーム全体にしてはならない。実装は禁止しないが、README に非推奨と書く。

サイズ:

| キー | 既定 | 意味 |
| --- | --- | --- |
| `DOC_MAX_FILES` | `30` | 1 ジョブのファイル数 |
| `DOC_MAX_FILE_BYTES` | `1048576` | 1 ファイル。超えたら先頭 1 MiB だけ読み、カードに切り詰めと書く |
| `DOC_MAX_DEPTH` | `4` | ディレクトリ深さ |
| `DOC_CHUNK_CHARS` | `3000` | チャンク長 |
| `DOC_CHUNK_OVERLAP` | `200` | 重なり |
| `DOC_MAX_CHUNKS` | `12` | 波 4 × 幅 3 |
| `DOC_TIMEOUT_S` | `180` | map から統合まで |

### 5.3 分割

Markdown は見出し（`#` から `###`）で切る。1 見出しが `DOC_CHUNK_CHARS` を超えたら文字数で再分割し、見出し名を各片に残す。見出しが無いテキストは文字数で切る。JSON はキー単位にせず、そのまま文字数で切る。整形はしない。

チャンク ID は `f3-c2`（ファイル通番、チャンク通番）。統合が引用する番号 `[n]` は、採用したカードの連番であり、チャンク ID とは別である。

### 5.4 計画と map

`doc_plan` は、質問とファイル一覧（パス、見出し、バイト数）だけを見る。本文は渡さない。

- モデル: LM Studio の 27B。検索の計画と同じ寿命。終わったら unload してから reader を起動する
- 出力: 読むチャンク ID を最大 12、優先順。失敗したら規則で「先頭から 12」に落とす
- 27B が載らないときは規則だけにする。失敗にしない

`doc_map`:

- 幅は `bonsai_select` と空きメモリ。上限 3。検索の reader と同じ Ternary-Bonsai-8B を優先する
- 1 波が終わったらプロセスを kill し、次の波で起動し直す。常駐させない
- 各ワーカーの入力はチャンク本文と質問だけ。他チャンクの本文は渡さない
- 出力は `EvidenceCard`。`source_type=file`、`locator` は `相対パス#見出し`、`quote` は 400 字以内の原文引用、`note` に数値・日付・決定・未決

ワーカーにツールは渡さない。ファイルを開くのはオーケストレータだけである。これは検索で「通信を開くのはオーケストレータだけ」としたのと同じ門である。

### 5.5 カバー

`doc_cover` は map が終わったカードの `locator` 一覧と、計画にあってまだ読んでいないチャンク ID を見る。本文は再投入しない。

- モデル: reader を殺したあとの Ternary-Bonsai-2-27B。検索の批評と同じ
- 追加で読む ID を最大 3 つ。残りチャンクが無く、または 4 波に達したら終了
- 同じチャンクの再読はオーケストレータが捨てる

統合は検索の `prompts/system_search.txt` を流用し、出典の書き方だけ「URL」を「パス#見出し」にする。抜粋に無い決定を書かない。

### 5.6 状態

チャット状態に足すキー:

| キー | 型 | 誰が書くか |
| --- | --- | --- |
| `doc_root_hit` | 文字列 | `doc_resolve`。表示用のルート名 |
| `doc_files` | パスと拒否理由 | オーケストレータ |
| `doc_chunks` | ID、locator、文字数 | 分割 |
| `evidence` | `EvidenceCard[]` | map。検証と共有 |
| `doc_waves` | 整数 | 波の回数 |

検索と文書を 1 ジョブで混ぜない。`/docs` のターンに検索意図があっても Tor は開かない。必要なら利用者が次のターンで `/search` する。

### 5.7 利用者に返すもの

進捗:

```text
許可: <root>
対象: 8 ファイル、拒否 2（.env、.gguf）
波 1/4: f1-c1, f1-c2, f2-c1
```

最終文は日本語。末尾に採用カードの `相対パス#見出し` を `[n]` で列挙する。読んでいない節が残っていれば 1 行、「未読の節がある。上限 12 チャンク」と付ける。

### 5.8 セキュリティ

- 読取はオーケストレータだけ。ワーカーの出力に含まれるパスを開かない
- パストラバーサル（`..`、ドライブをまたぐ指定、NTFS の代替データストリーム）は `doc_resolve` で拒否
- 拒否ファイルは一覧に名前だけ出し、中身は進捗にもモデルにも渡さない
- チャンクはプロンプトとして扱い、中の命令文でルートを広げない
- 文書ジョブは Tor を起動しない。既に Tor が居ても、この分岐からはソケットを開かない
- ロックの寿命は検索と同じ。タイムアウト `JOB_LOCK_TIMEOUT_S`（現行 30 秒）で取れなければキューしない

### 5.9 エラー

| 条件 | 利用者向け |
| --- | --- |
| ルート未設定 | 「LOCAL_DOC_ROOTS が未設定です」 |
| ルート外 | 「許可したディレクトリの外です」 |
| 対象 0 件 | 「読めるテキストがありません」 |
| すべて拒否名 | 拒否理由だけ。中身は出さない |
| reader が起動できない | 現行の「検証を通過した重みが無い、またはメモリ不足」 |
| ロック失敗 | 「画像タブが実行中です」 |
| 制限時間 | 読めたカードだけで統合する。0 件なら打ち切りと返す |

## 7. 実装順

1. `doc_resolve` と拒否テスト。モデルなし
2. 分割。見出しと切り詰め
3. `/docs` の分岐と、ルート未設定の文言
4. 計画（27B）と、失敗時の規則フォールバック。計画後に unload することをログで確認する
5. map を幅 3、1 波だけ。カードが `EvidenceCard` になっていること
6. 波を 4 まで。同じチャンクを捨てること
7. 統合。出典がパスであること
8. 別紙の検証段が既にあれば接続する。無ければ統合で止める

## 8. リスク

- リポジトリルートを許可すると、拒否名の漏れで秘密がプロンプトに入る。拒否は許容リストより先に掛ける
- ログファイルは秘密を含みうる。`.log` を既定で許すのは、利用者がルートを絞ることが前提である。広いルートでは `.log` を外す設定を README に書く
- 幅 3 と波 4 では、長い設計書の後半が落ちる。未読行を出して、利用者がパスを絞る前提にする
- 27B の計画はファイル一覧だけで誤った優先をする。規則フォールバック（先頭から）を残す
- 検索と文書で `evidence` キーを共有するため、1 ジョブで両方走らせると番号が混ざる。route で排他にする
